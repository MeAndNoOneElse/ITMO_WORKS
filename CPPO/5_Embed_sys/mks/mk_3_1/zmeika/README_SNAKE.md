# Змейка — SDK-1.1MC.427 / STM32CubeIDE

В папке `tetris` реализована **«Змейка», вариант 1 МК3**. Имя проекта оставлено прежним,
поэтому обычная сборка CubeIDE называется `tetris.elf`. Это игра «Змейка».

На странице 48 МК3 указаны два варианта: «Змейка» и «Тетрис»; FreeRTOS обязателен.
Число задач, размеры стеков, частота процессора, звук и UART в задании не предписаны.
Выбранные ниже параметры — реализация этого проекта, а не дополнительные требования методички.

## Запуск в существующем STM32CubeIDE

1. Выбрать проект `tetris` и нажать **F5 / Refresh**, чтобы IDE увидела новые исходники.
2. Выполнить **Project → Build Project**. Все игровые `.c` находятся в `Core/Src`,
   заголовки — в `Core/Inc`, HAL I²C добавлен в `Drivers`.
3. Выбрать конфигурацию **Snake SDK427** и файл `Debug/tetris.elf`.
   Проверить путь в **Debug Configurations → C/C++ Application**.
4. Запустить отладку и нажать **Resume** после остановки в `main`.
5. На OLED появится `SNAKE / SB6: PLAY`. Нажать **SB6**.

Код уже написан: повторная генерация CubeMX для первой сборки не требуется.
Изменённый `tetris.ioc` содержит I²C и три задачи. Дополнительные объекты IPC
создаются в `App_Init()` из секции `USER CODE BEGIN RTOS_MUTEX`.
Проверена компиляция исходников ARM GCC; автоматическая перегенерация через GUI CubeMX
в этой работе не запускалась. После будущей генерации проверить сохранение вызовов
`Board_Init`, `App_Init`, `App_InputTask`, `App_GameTask`, `App_DisplayTask`
и определения `INCLUDE_vTaskDelayUntil=1`.

### Сборка без запуска IDE

Из PowerShell в каталоге проекта:

```powershell
.\build_snake.ps1
```

Скрипт использует установленный STM32CubeIDE 1.19.0 и полностью компилирует HAL,
FreeRTOS, startup и приложение. Для другого расположения IDE:

```powershell
.\build_snake.ps1 -CubeIdeRoot 'C:\ST\STM32CubeIDE_1.19.0\STM32CubeIDE'
```

Результаты: `BuildSnake/snake.elf`, `snake.hex`, `snake.bin`, `snake.map`.
Адрес размещения BIN во Flash: **0x08000000**.
Для отладки этой сборки выбрать `BuildSnake/snake.elf` в существующей конфигурации SDK.
Скрипт только собирает файлы; прошивка устройства автоматически не выполняется.

## Управление

Используется матричная клавиатура несущей платы, обозначения кнопок **SB** по схеме.
Кнопка SB1 на процессорном модуле — другая кнопка и в игре не используется.

```text
SB1     SB5 ↑     SB9
SB2 ←   SB6       SB10 →
SB3     SB7 ↓     SB11
SB4     SB8       SB12
```

| Кнопка | Действие |
|---|---|
| SB5 | Вверх |
| SB7 | Вниз |
| SB2 | Влево |
| SB10 | Вправо |
| SB6 | Старт, пауза, продолжение; после поражения/победы — новая игра |
| SB8 | Немедленно начать новую игру |

Один фронт нажатия даёт одно событие; удержание кнопки не переключает паузу повторно.
Подавление дребезга: три одинаковых опроса с периодом 10 мс. Одновременные нажатия
отбрасываются, так как матрица не имеет индивидуальных диодов против ложных комбинаций.
Направление принимается не более одного раза за шаг движения; разворот на 180° запрещён.
Слишком частые повороты в одном шаге игнорируются.

## Правила и экран

- Поле 30 × 12 клеток, одна клетка 4 × 4 пикселя. Начальная длина — 4.
- Крестик — еда, квадрат с пустой серединой — голова.
- За еду начисляется одно очко и добавляется сегмент.
- Начальный период шага 300 мс; каждые 3 очка уменьшается на 20 мс, минимум 80 мс.
- Столкновение со стеной или телом завершает игру. Прохода сквозь стены нет.
- Вход в клетку уходящего хвоста допустим при обычном движении.
- Заполнение всех 360 клеток означает победу. Генерация еды не зависает на заполненном поле.
- `SCORE` — текущий счёт, `BEST` — рекорд с момента включения. После сброса питания рекорд теряется.
- Зелёный светодиод показывает активную игру; двухцветный — паузу/готовность либо поражение/ошибку.

## Настройки микроконтроллера и CubeMX

| Раздел | Параметр |
|---|---|
| MCU | STM32F427VIT6, LQFP100 |
| RCC | HSI 16 МГц, PLL выключен; сохранена исходная частота проекта |
| SYS → Debug | JTAG 5 pins, сохранён интерфейс штатного отладчика |
| SYS → Timebase Source | TIM6, HAL tick 1 мс |
| FreeRTOS Interface | CMSIS_V1; ядро FreeRTOS V10.3.1 из проекта |
| I2C1 | PB8 SCL / PB9 SDA, AF4, open drain, pull-up, 100 кГц |
| GPIO | PD13, PD14, PD15 — push-pull output |
| SysTick / PendSV | Приоритет 15 |
| TIM6_DAC | Приоритет 15, обслуживает HAL_IncTick |
| FreeRTOS max syscall interrupt priority | 5 |

HSI 16 МГц достаточно для игры. I²C 100 кГц выбран для спокойной работы с платой
и её подтяжками; передача дисплея разбита на страницы, чтобы клавиатура могла получить шину.
TIM6 занят системной базой времени HAL. Пищалка PE9 использует PWM TIM1_CH1.
В задачах ожидание выполняется через FreeRTOS. Короткие `HAL_Delay` при аппаратном сбросе OLED
составляют суммарно 4 мс и выполняются только при инициализации/восстановлении дисплея.

### FreeRTOS

| Задача CubeMX | Функция | CMSIS приоритет | Стек, слова по 4 байта | Назначение |
|---|---|---|---|---|
| defaultTask | StartDefaultTask → App_InputTask | AboveNormal (+1) | 384 / 1536 байт | Клавиатура каждые 10 мс |
| myTask02 | StartTask02 → App_GameTask | Normal (0) | 512 / 2048 байт | Единственный владелец игровой модели |
| displayTask | StartDisplayTask → App_DisplayTask | BelowNormal (-1) | 512 / 2048 байт | OLED и отрисовка |

В данной STM32-обёртке CMSIS_V1 `osThreadCreate` передаёт размер стека непосредственно
в `xTaskCreate`, поэтому значения таблицы указаны в **словах**, а не в байтах.

- Вытесняющее планирование `configUSE_PREEMPTION=1`, квантование `configUSE_TIME_SLICING=1`.
- Tick 1000 Гц; максимальное число приоритетов 7; heap_4, куча 15360 байт.
- `INCLUDE_vTaskDelayUntil=1`: периодический опрос клавиш.
- `configUSE_MUTEXES=1`: мьютекс I²C с наследованием приоритета.
- `configCHECK_FOR_STACK_OVERFLOW=2`, `configUSE_MALLOC_FAILED_HOOK=1`:
  при ошибке вызывается `Error_Handler`.
- Idle task использует статическое выделение; прикладные задачи, очереди и мьютекс — динамическое.

IPC создаётся в `app_game.c`:

1. `input_queue`: 8 элементов `uint8_t`. Передаёт номер SB от клавиатуры игре.
   При переполнении новое нажатие отбрасывается, счётчик `input_dropped` растёт.
2. `frame_queue`: один элемент `Snake`, передаваемый копированием.
   `xQueueOverwrite` оставляет последнее состояние для дисплея.
3. `bus_mutex`: защищает все обращения к OLED и PCA9538 после запуска планировщика.
   Дисплей освобождает его после каждой страницы. Отрисовка в RAM выполняется без мьютекса.

Вложенных захватов мьютексов нет. Игровая задача не обращается к I²C и не зависит
от скорости дисплея. У дисплея и игры разные копии состояния. Бинарные семафоры и
программные таймеры не добавлены: отдельного требования использовать все виды IPC в МК3 нет.

## Подключение периферии

| Устройство | 7-битный I²C адрес | Адрес в HAL, сдвинутый влево |
|---|---|---|
| SSD1306 OLED 128×64 | 0x3C | 0x78 |
| PCA9538, сброс OLED на P0 | 0x70 | 0xE0 |
| PCA9538, клавиатура | 0x71 | 0xE2 |

P0–P3 расширителя клавиатуры — строки, P4–P6 — столбцы.
При сканировании одна строка выводит 0, остальные остаются входами.
P0 расширителя дисплея переключается 1 → 0 → 1, прочие выводы сохраняются.
Адреса и разводка сверены с учебным пособием, схемой и примерами SDK.

## Проверки и ограничения

Полная сборка `build_snake.ps1` прошла ARM GCC 13.3.1. Размеры:
`text=21920`, `data=96`, `bss=20896` байт; Flash для text+data — 22016 байт.
Предупреждения `-Wextra` относятся к неиспользуемым параметрам штатной CMSIS-обёртки;
прикладные файлы собрались без предупреждений.

Тесты запускаются командой:

```powershell
.\tests\run_tests.ps1
```

Скрипт по умолчанию использует MinGW из установленного CLion; можно указать другой
Windows GCC через `-Compiler`. Проверены начальное состояние, пауза, запрет разворота,
рост, стены, столкновение с телом, уход хвоста, победа, ограничение скорости,
50 000 шагов с проверкой целостности и границы кадрового буфера.
`tests/oled-preview.png` — увеличенные экраны, полученные из функции `Game_Render`.

**06.10.2026 прошивка загружена в подключённую плату, OpenOCD: Verified OK.**
После запуска подтверждены четыре задачи (три прикладные и Idle), рост счётчика тиков,
нулевой счётчик ошибок I²C и отсутствие флагов ошибок клавиатуры/дисплея.
Ориентацию OLED, реальное нажатие кнопок и запас стеков под игровой нагрузкой
необходимо подтвердить вручную на стенде.
При отсутствии изображения проверить питание платы и общий I²C. Для отладки доступны
`board_i2c_errors`, `input_dropped`, handles задач и состояние `game`.
При ошибке дисплея выполняется повторная инициализация; ошибка начальной настройки
клавиатуры останавливает запуск в `Error_Handler`.

### Исправление запуска и JTAG (06.10.2026)

Первоначальная загрузка остановилась на настройке клавиатуры: SDA (PB9) была в нуле,
I²C SR2 показывал BUSY, HAL возвращал TIMEOUT. Теперь `Board_Init` перед обращением
к устройствам освобождает шину девятью тактами SCL и STOP, затем сбрасывает и включает
I²C1. Это занимает около 24 мс только при старте, до FreeRTOS.
Основание: раздел Bus clear спецификации [NXP UM10204](https://www.nxp.com/docs/en/user-guide/UM10204.pdf).

В `SDK_11M.cfg` установлен JTAG 500 кГц, описан второй TAP с ID 0x06419041,
обновлён синтаксис FTDI и включено соединение под сбросом.
В конфигурациях `Snake SDK427.launch` и `tetris Debug (1).launch` отключён Live Expressions.
Предыдущие настройки сохранены в `backup_debug_config`.
Если CubeIDE продолжает запускать старую сессию: Terminate, F5, затем
Run → Debug Configurations → Snake SDK427 → Debug. При остановке на main нажать F8.

## Звуки игры

Яблоко: 2000 Гц, 60 мс. Game Over: 880 → 660 → 440 → 220 Гц,
первые три ноты по 120 мс, последняя 220 мс. Пауза и перезапуск отключают звук.
Драйвер находится в board_game.c: sound_init, Board_SoundPlay, Board_SoundUpdate.
TIM1_CH1 / PE9 работает в PWM с заполнением 50%; вне сигнала CCR1=0.
HAL tick перенесён на TIM6, FreeRTOS по-прежнему использует SysTick.
Звук обслуживается игровой задачей каждые 10 мс без блокирующих задержек.
Настройки отражены в tetris.ioc. Исходники до изменений — в backup_before_sound.

Прошивка загружена на подключённую плату: Verified OK. В аппаратной проверке
через отладчик созданы условия поедания яблока и столкновения. Подтверждены
SOUND_APPLE и SOUND_GAME_OVER из игровой задачи, PWM ARR/CCR1=499/250 для яблока
и 1135/568 для первого тона проигрыша. После обоих сигналов CCR1=0.
Четыре задачи работают, ошибок I²C нет. В конце выполнен сброс к стартовому экрану.
Громкость и тембр на слух не проверялись.
