\abstract{
В данной работе проведён анализ данных эксперимента по сравнению производительности двух способов доступа к файлу (read/lseek и mmap) при различных режимах работы с кэшем (cached / no-cache) и разных топологиях графа (последовательная / случайная). Основная особенность исходных данных — разное количество итераций в конфигурациях (10, 1, 200), что потребовало нормализации метрики wall\_time на одну итерацию для корректного сравнения. Выполнен статистический анализ с расчётом 95\% доверительных интервалов, построены графики сравнения и сделаны выводы о влиянии режима кэширования и способа доступа на производительность.

\section{Цель работы}
Основная цель — провести корректный статистический анализ данных эксперимента \texttt{results\_all.csv}, нормализовать метрики с учётом разного количества итераций, построить графики и сформулировать выводы о влиянии паттерна доступа, режима кэширования и способа доступа (read vs mmap) на производительность.

\section{Подготовка данных и описание эксперимента}
Данные содержатся в файле \texttt{results\_all.csv}, сгенерированном скриптом \texttt{run\_experiment.sh}. Каждая строка содержит метрики одного запуска:
\begin{itemize}
    \item \texttt{run\_id} — номер повторения (3--22, без прогрева);
    \item \texttt{load} — тип нагрузки (\texttt{read}, \texttt{write});
    \item \texttt{app} — приложение (\texttt{graph\_traverse}, \texttt{graph\_traverse\_mmap});
    \item \texttt{mode} — режим кэша (\texttt{cached}, \texttt{no-cache});
    \item \texttt{graph} — файл графа (\texttt{graph-seq.bin}, \texttt{graph-rand.bin});
    \item \texttt{iter} — количество итераций обхода в данном запуске;
    \item \texttt{wall\_s}, \texttt{user\_s}, \texttt{sys\_s}, \texttt{cpu\_pct}, \texttt{minflt}, \texttt{majflt}, \texttt{vol\_ctx}, \texttt{invol\_ctx}, \texttt{maxrss\_kb}, \texttt{fs\_in\_blocks}, \texttt{fs\_out\_blocks}.
\end{itemize}

\subsection{Особенность данных: разное количество итераций}
В одной серии экспериментов используются разные значения \texttt{iter} для разных приложений и режимов:
\begin{itemize}
    \item \texttt{graph\_traverse}, \texttt{cached} — 10 итераций;
    \item \texttt{graph\_traverse}, \texttt{no-cache} — 1 итерация;
    \item \texttt{graph\_traverse\_mmap}, \texttt{cached} и \texttt{no-cache} — 200 итераций.
\end{itemize}
Это означает, что прямое сравнение \texttt{wall\_s} между конфигурациями некорректно: запуск с 200 итерациями естественно длится дольше, чем с одной. Для корректного сравнения производительности метрику \texttt{wall\_s} необходимо нормализовать на одну итерацию:
\[
    \text{mean\_norm} = \frac{\texttt{wall\_s}}{\texttt{iter}}
\]
Это даёт «время выполнения полного обхода графа» независимо от числа повторений и позволяет сравнивать конфигурации между собой.

\section{Гипотеза}
Ожидается, что:
\begin{enumerate}
    \item Последовательный граф (\texttt{graph-seq.bin}) будет быстрее случайного (\texttt{graph-rand.bin}) из-за лучшей пространственной локальности (меньше page faults, лучше кэш);
    \item Режим \texttt{cached} значительно быстрее \texttt{no-cache} для \texttt{read} из-за отсутствия системного кэширования;
    \item Для \texttt{mmap} разница между \texttt{cached} и \texttt{no-cache} будет минимальной, т.к. механизм отображения памяти работает иначе (страничные ошибки при доступе, а не при чтении);
    \item Нормализация на одну итерацию покажет статистически значимые различия (ДИ не пересекаются) для основных конфигураций.
    \item Режим \texttt{write} (нагрузка с записью) будет медленнее \texttt{read} из-за дополнительных операций записи в файл и выделения страниц памяти, особенно для \texttt{read}, тогда как для \texttt{mmap} разница будет меньше из-за страничного механизма отображения.
\end{enumerate}

\section{Методология анализа}
\subsection{Нормализация}
Для каждой строки \texttt{results\_all.csv} рассчитано нормализованное значение:
\[
    x_{norm} = \frac{\texttt{wall\_s}}{\texttt{iter}}
\]
Это значение интерпретируется как время выполнения одного полного обхода графа при заданной конфигурации.

\subsection{Статистическая обработка}
Для каждой из 16 конфигураций (2 приложения $\times$ 2 режима кэша $\times$ 2 графа $\times$ 2 типа нагрузки) рассчитаны:
\begin{itemize}
    \item выборочное среднее $\bar{x}$;
    \item несмещённое стандартное отклонение $s$ (знаменатель $N-1$);
    \item стандартная ошибка среднего $SE = s / \sqrt{N}$;
    \item 95\% доверительный интервал: $\bar{x} \pm t_{0.025,19} \cdot SE \approx \bar{x} \pm 2.093 \cdot SE$ (t-распределение Стьюдента, $df = N - 1 = 19$);
    \item медиана, минимум, максимум нормализованных значений.
\end{itemize}

Прогревочные запуски не использовались (первые 2 прогревочных (run_id 1, 2) исключены, анализ на N=20 (run_id 3-22)), т.к. данные собраны в режиме интерливинга и прогрев не был предусмотрен методикой скрипта сбора. Выбросы не удалялись, т.к. формальных критериев исключения (например, $>3\sigma$) в данных нет, и все значения лежат в разумных пределах.

\section{Анализ результатов}

\subsection{Сравнение seq и rand}
Для \texttt{graph\_traverse} (read) нормализованное время для \texttt{seq} и \texttt{rand} практически одинаково (разница менее 0.3\%). Для \texttt{graph\_traverse\_mmap} (mmap) разница также минимальна ($\sim$1--2\%). Это означает, что в данных условиях (небольшой граф, SSD, ОС с эффективным кэшированием) разница в пространственной локальности не проявляется в значимой степени для времени выполнения одной итерации. Однако для \texttt{no-cache} режима результаты существенно выше, что указывает на доминирующее влияние системных вызовов и дискового ввода-вывода.

\subsection{Влияние режима кэширования}
Для \texttt{read} режим \texttt{no-cache} увеличивает нормализованное время примерно в $40\times$ (с $\sim$0.28 с до $\sim$11.5 с). Это ожидаемый результат: отключение файлового кэша через \texttt{O\_DIRECT} или аналогичный механизм приводит к прямому чтению с диска для каждой операции \texttt{read}, что значительно замедляет обход.

Для \texttt{mmap} разница между \texttt{cached} и \texttt{no-cache} составляет всего $2$--$5$\% ($\sim$0.023 с против $\sim$0.024 с). Это объясняется механизмом работы \texttt{mmap()}: файл отображается в адресное пространство, и страничные ошибки происходят при первом доступе к страницам. Даже при использовании \texttt{MADV\_RANDOM} (или аналогичного механизма отключения кэша для mmap) накладные расходы на чтение с диска распределяются между страницами, а не на каждый вызов \texttt{read}, поэтому влияние режима кэширования минимально.

\subsection{Сравнение read и mmap}
Нормализованное время для \texttt{mmap} ($\sim$0.024 с) примерно в 12 раз меньше, чем для \texttt{read/cached} ($\sim$0.28 с). Это отражает преимущество отображения файла в память: отсутствие системных вызовов \texttt{read}/\texttt{lseek} для каждой вершины графа позволяет значительно сократить время обхода.

\subsection{Сравнение памяти и страничных ошибок (page faults)}
Данные \texttt{maxrss\_kb}, \texttt{majflt} и \texttt{minflt} из \texttt{results\_all.csv} (без прогрева, $N=20$) позволяют дополнить сравнение \texttt{read} и \texttt{mmap} количественными метриками памяти и страничных ошибок (таблица~\ref{tab:mem}). Основные наблюдения:
\begin{itemize}
    \item \textbf{Память ($\texttt{maxrss\_kb}$):} \texttt{mmap} использует примерно в $2.2$ раза больше памяти, чем \texttt{read} ($\sim3420$~КБ против $\sim1568$~КБ), т.к. весь файл отображается в виртуальное адресное пространство процесса, тогда как \texttt{read} использует только буфер процесса.
    \item \textbf{Minor page faults ($\texttt{minflt}$):} для \texttt{mmap} в режиме \texttt{cached} значение $\sim8076$ на запуск (в среднем $\sim400$/итерацию при $200$ итерациях) значительно выше, чем для \texttt{read} ($\sim75$). Это отражает механизм страничных ошибок при первом доступе к отображённым страницам.
    \item \textbf{Major page faults ($\texttt{majflt}$):} для \texttt{mmap} в режиме \texttt{no-cache} наблюдается $\sim512$ страничных ошибок на запуск (чтение страниц с диска без кэша), тогда как в \texttt{cached} режиме $\sim0$ (страницы остаются в кэше ОС). Для \texttt{read} значение $\sim1$ в обоих режимах, что указывает на отсутствие массового чтения с диска при отсутствии кэша (хотя время выполнения резко возрастает из-за явных вызовов \texttt{read}).
\end{itemize}

\subsubsection*{Примечание о системных вызовах ($\texttt{syscalls}$)}
Количественный подсчёт системных вызовов ($\texttt{syscalls}$) не представлен в \texttt{results\_all.csv} и не рассчитывается в \texttt{analysis.py}. Однако качественное сравнение из методологии работы остаётся корректным: \texttt{mmap} устраняет явные вызовы \texttt{read()} и \texttt{lseek()} на каждую вершину графа, что напрямую объясняет снижение нормализованного времени ($\sim12\times$) и снижение \texttt{sys\_s} (времени в ядре) для \texttt{mmap} по сравнению с \texttt{read}.

\subsection{Достаточность числа измерений}
При $N = 20$ стандартная ошибка среднего для \texttt{mmap/cached} составляет $\sim$0.0001 с, что даёт очень узкий 95\% ДИ ($\pm$0.0004 с при $t_{0.025,19} \approx 2.093$). Для \texttt{read/no-cache} SE $\sim$0.036 с, ДИ $\pm$0.075 с — это $\sim$0.65\% от среднего, что вполне достаточно для уверенного различия конфигураций. Увеличение $N$ до 60 уменьшит ширину ДИ примерно в $\sqrt{2}$ раз ($\approx 0.7$ от текущей, т.к. $t_{0.025,59} \approx 2.001 \approx t_{0.025,19}$), но прирост информации будет незначительным, т.к. текущие интервалы (рассчитанные по t-распределению Стьюдента) уже позволяют различать конфигурации с высокой уверенностью.

\section{Выводы}
\begin{enumerate}
    \item \textbf{Нормализация необходима.} Прямое сравнение \texttt{wall\_s} между конфигурациями с разными \texttt{iter} некорректно. Нормализация на одну итерацию даёт корректную метрику для оценки производительности доступа к данным.
    \item \textbf{Влияние кэша на read критично.} Отключение кэша увеличивает время в $\sim$40 раз, что подтверждает значимость файлового кэша ОС для сценариев с частыми небольшими чтениями.
    \item \textbf{mmap менее чувствителен к режиму кэша.} Разница между \texttt{cached} и \texttt{no-cache} для \texttt{mmap} составляет менее 5\%, что объясняется механизмом страничных ошибок при отображении памяти.
    \item \textbf{mmap значительно быстрее read.} Даже при кэшированном режиме \texttt{mmap} в $\sim$12 раз быстрее \texttt{read}, что демонстрирует преимущество отображения файла в адресное пространство для обхода структур данных.
    \item \textbf{Разница seq/rand незначительна.} В данных условиях пространственная локальность не приводит к статистически значимой разнице во времени выполнения одной итерации для обеих топологий графа.
    \item \textbf{Достаточность N подтверждена.} При $N = 20$ (df = 19) доверительные интервалы рассчитаны по t-распределению Стьюдента ($t_{0.025,19} \approx 2.093$) и достаточно узкие для уверенных выводов о различии конфигураций. Увеличение $N$ до 60 ($df = 59$, $t_{0.025,59} \approx 2.001$) уменьшит ширину ДИ примерно в $\sqrt{2}$ раз ($\approx 0.7$ от текущей), но прирост информации будет незначительным.
    \item \textbf{Write медленнее read.} Режим $\texttt{load}=\texttt{write}$ увеличивает нормализованное время в $\sim 4$--$5$ раз для $\texttt{read}$ (cached: $0.1537$ с/ит против $0.0329$ с/ит) и в $\sim 1.5$--$3$ раза для $\texttt{mmap}$ (cached: $0.0020$ с/ит против $0.0012$ с/ит), что подтверждает влияние операций записи и выделения страниц на производительность.
\end{enumerate}

    \item \textbf{Анализ и выводы} — статистическая обработка (\texttt{analysis.py}: среднее, $s$, $SE$, 95\% ДИ по $t_{0.025,19}$), построение графиков (\texttt{pairwise\_1..8.png}, \texttt{all\_config\_normalized.png}), формулирование выводов.
\end{enumerate}

\subsection{Обоснование нормализации}
Нормализация необходима для корректного сравнения конфигураций с разным количеством итераций. Без неё запуск с 200 итерациями всегда будет выглядеть значительно дольше запуска с одной итерацией, даже если эффективность доступа к данным выше. Нормализованная метрика (сек / итерацию) устраняет это и позволяет оценивать именно эффективность паттерна доступа, что соответствует цели эксперимента.

\subsection{Приложение: полные Python- и Bash-скрипты для сбора и анализа данных}

\subsubsection*{Сбор данных (\texttt{lab_0/prog/run\_experiment.sh})}
\begin{verbatim}
#!/usr/bin/env bash
set -euo pipefail
N=22
ITER_READ_CACHED=20
ITER_READ_NOCACHE=1
ITER_MMAP_CACHED=400
ITER_MMAP_NOCACHE=400
ITER_WRITE_CACHED=20
ITER_WRITE_NOCACHE=1
ITER_WRITE_MMAP_CACHED=400
ITER_WRITE_MMAP_NOCACHE=300

BIN_DIR=../../intro-exp/out
DATA_DIR=../data
OUT="$DATA_DIR/results_all.csv"
for f in "$DATA_DIR/graph-seq.bin" "$DATA_DIR/graph-rand.bin"; do
  [[ -f "$f" ]] || { echo "нет файла $f"; exit 1; }
done
for b in graph_traverse graph_traverse_mmap; do
  [[ -x "$BIN_DIR/$b" ]] || { echo "нет бинарника $BIN_DIR/$b"; exit 1; }
done

echo "run_id,load,app,mode,graph,iter,wall_s,user_s,sys_s,cpu_pct,minflt,majflt,vol_ctx,invol_ctx,maxrss_kb,fs_in_blocks,fs_out_blocks" > "$OUT"

drop_cache() {
  sync
  echo 3 | sudo tee /proc/sys/vm/drop_caches > /dev/null
}

warm_cache() {
  cat "$1" > /dev/null
}

run_one() {
  local app="$1" load="$2" mode="$3" graph="$4" iter="$5" i="$6"
  local flags=()
  if [[ "$load" == "write" ]]; then
    flags+=(--write)
  fi

  if [[ "$mode" == "no-cache" ]]; then
    drop_cache
    flags+=(--no-cache)
  else
    warm_cache "$DATA_DIR/$graph"
  fi

  local fmt="$i,$load,$app,$mode,$graph,$iter,%e,%U,%S,%P,%R,%F,%w,%c,%M,%I,%O"

  /usr/bin/time -f "$fmt" -a -o "$OUT" \
    "$BIN_DIR/$app" "${flags[@]}" "$iter" "$DATA_DIR/$graph" > /dev/null
}

for i in $(seq 1 "$N"); do
  run_one graph_traverse      read  cached   graph-seq.bin  "$ITER_READ_CACHED"        "$i"
  run_one graph_traverse      read  cached   graph-rand.bin "$ITER_READ_CACHED"        "$i"
  run_one graph_traverse      read  no-cache graph-seq.bin  "$ITER_READ_NOCACHE"       "$i"
  run_one graph_traverse      read  no-cache graph-rand.bin "$ITER_READ_NOCACHE"       "$i"

  run_one graph_traverse_mmap read  cached   graph-seq.bin  "$ITER_MMAP_CACHED"        "$i"
  run_one graph_traverse_mmap read  cached   graph-rand.bin "$ITER_MMAP_CACHED"        "$i"
  run_one graph_traverse_mmap read  no-cache graph-seq.bin  "$ITER_MMAP_NOCACHE"       "$i"
  run_one graph_traverse_mmap read  no-cache graph-rand.bin "$ITER_MMAP_NOCACHE"       "$i"

  run_one graph_traverse      write cached   graph-seq.bin  "$ITER_WRITE_CACHED"       "$i"
  run_one graph_traverse      write cached   graph-rand.bin "$ITER_WRITE_CACHED"       "$i"
  run_one graph_traverse      write no-cache graph-seq.bin  "$ITER_WRITE_NOCACHE"      "$i"
  run_one graph_traverse      write no-cache graph-rand.bin "$ITER_WRITE_NOCACHE"      "$i"

  run_one graph_traverse_mmap write cached   graph-seq.bin  "$ITER_WRITE_MMAP_CACHED"  "$i"
  run_one graph_traverse_mmap write cached   graph-rand.bin "$ITER_WRITE_MMAP_CACHED"  "$i"
  run_one graph_traverse_mmap write no-cache graph-seq.bin  "$ITER_WRITE_MMAP_NOCACHE" "$i"
  run_one graph_traverse_mmap write no-cache graph-rand.bin "$ITER_WRITE_MMAP_NOCACHE" "$i"
done

echo "готово: $OUT"
\end{verbatim}

\begin{verbatim}
#!/usr/bin/env python3
# Очень простой, компактный анализ с комментариями
import csv, statistics, os
from collections import defaultdict
import matplotlib.pyplot as plt

CSV_FILE = "../data/results_all.csv"
GRAPHICS_DIR = "../graphics"
os.makedirs(GRAPHICS_DIR, exist_ok=True)

records = []
with open(CSV_FILE, newline="") as f:
    for row in csv.DictReader(f):
        run_id = int(row["run_id"])
        if run_id <= 2:
            continue
        if run_id > 22:
            continue
        for k in row:
            if k == "run_id":
                row[k] = int(row[k])
            elif k in ("app", "mode", "graph"):
                pass
            else:
                try:
                    row[k] = float(row[k])
                except ValueError:
                    pass
        records.append(row)

groups = defaultdict(list)
for r in records:
    load = r.get("load", "read")
    groups[(load, r["app"], r["mode"], r["graph"])].append(r)

stats = {}
for key, rows in groups.items():
    values = [r["wall_s"] / r["iter"] for r in rows]
    mean_v = statistics.mean(values)
    std_v = statistics.stdev(values) if len(values) > 1 else 0.0
    se = std_v / (len(values) ** 0.5)
    t_95 = 2.093
    ci_95 = t_95 * se
    stats[key] = {
        "mean": mean_v, "std": std_v, "se": se, "ci": ci_95,
        "median": statistics.median(values),
        "min": min(values), "max": max(values),
        "n": len(values), "raw_iter": rows[0]["iter"],
        "maxrss_mean": statistics.mean([r["maxrss_kb"] for r in rows]),
        "majflt_mean": statistics.mean([r["majflt"] for r in rows]),
        "minflt_mean": statistics.mean([r["minflt"] for r in rows]),
    }

# Пары для графиков сравнения
pairs = [
    ("read (cached) seq vs rand", ("read","graph_traverse","cached","graph-seq.bin"), ("read","graph_traverse","cached","graph-rand.bin"), "graph"),
    ("read (cached) vs no-cache", ("read","graph_traverse","cached","graph-seq.bin"), ("read","graph_traverse","no-cache","graph-seq.bin"), "mode"),
    ("cached: read vs mmap (seq)", ("read","graph_traverse","cached","graph-seq.bin"), ("read","graph_traverse_mmap","cached","graph-seq.bin"),"app"),
    ("read (no-cache) seq vs rand", ("read","graph_traverse","no-cache","graph-seq.bin"), ("read","graph_traverse","no-cache","graph-rand.bin"), "graph"),
    ("mmap (cached) seq vs rand", ("read","graph_traverse_mmap","cached","graph-seq.bin"), ("read","graph_traverse_mmap","cached","graph-rand.bin"),"graph"),
    ("mmap (cached) vs no-cache", ("read","graph_traverse_mmap","cached","graph-rand.bin"), ("read","graph_traverse_mmap","no-cache","graph-rand.bin"),"mode"),
    ("cached (rand): read vs mmap", ("read","graph_traverse","cached","graph-rand.bin"), ("read","graph_traverse_mmap","cached","graph-rand.bin"),"app"),
    ("no-cache (rand): read vs mmap", ("read","graph_traverse","no-cache","graph-rand.bin"), ("read","graph_traverse_mmap","no-cache","graph-rand.bin"),"app"),
    ("read vs write (cached, seq)", ("read","graph_traverse","cached","graph-seq.bin"), ("write","graph_traverse","cached","graph-seq.bin"), "load"),
    ("read vs write (mmap, cached)", ("read","graph_traverse_mmap","cached","graph-seq.bin"), ("write","graph_traverse_mmap","cached","graph-seq.bin"), "load"),
]

for i, (label, k1, k2, suffix) in enumerate(pairs, 1):
    if k1 not in stats or k2 not in stats:
        print(f"Пропуск пары {i}: нет данных для {k1} или {k2}")
        continue
    fig, ax = plt.subplots(figsize=(8, 6))
    colors = ["#66c2a5", "#fc8d62"]
    if suffix == "graph":
        labels_bars = [k1[3].replace("graph-","").replace(".bin",""), k2[3].replace("graph-","").replace(".bin","")]
    elif suffix == "mode":
        labels_bars = [k1[2], k2[2]]
    elif suffix == "app":
        labels_bars = [k1[1].replace("graph_",""), k2[1].replace("graph_","mmap")]
    elif suffix == "load":
        labels_bars = [k1[0], k2[0]]
    means = [stats[k1]["mean"], stats[k2]["mean"]]
    stds  = [stats[k1]["std"],  stats[k2]["std"]]
    bars = ax.bar(labels_bars, means, yerr=stds, capsize=5, color=colors, edgecolor="black", alpha=0.85)
    ymin = min(means[j] - stds[j] for j in range(2))
    ymax = max(means[j] + stds[j] for j in range(2))
    ax.set_ylim(max(0, ymin*0.95), ymax*1.15)
    ax.set_ylabel("Нормализованное время (сек / итерацию)")
    ax.set_title(f"{label}\\n({suffix})\\nN=20, df=19, t≈2.093", fontsize=11, pad=12)
    desc = f"Сравнение: {label.replace(chr(10), ' ')} | параметр: {suffix}"
    ax.text(0.5, -0.22, desc, transform=ax.transAxes, fontsize=9, ha="center", va="top", bbox=dict(boxstyle="round,pad=0.3", facecolor="#f0f0f0", alpha=0.9))
    ax.grid(axis="y", linestyle="--", alpha=0.5)
    ax.set_axisbelow(True)
    for bar, val in zip(bars, means):
        ax.annotate(f"{val:.2e}", xy=(bar.get_x()+bar.get_width()/2, bar.get_height()),
                    xytext=(0, 3), textcoords="offset points", ha="center", va="bottom", fontsize=8)
    fig.tight_layout()
    path = os.path.join(GRAPHICS_DIR, f"pairwise_{i}.png")
    fig.savefig(path, dpi=200)
    plt.close(fig)
    print(f"График {i}/10 сохранён: {path}")

fig_all, ax_all = plt.subplots(figsize=(8, 5))
short = []
vals = []
errs = []
for k in sorted(stats):
    load_s = k[0]
    app_s = "read" if k[1] == "graph_traverse" else ("mmap" if k[1] == "graph_traverse_mmap" else k[1])
    mode_s = k[2]
    graph_s = "seq" if k[3] == "graph-seq.bin" else "rand"
    short.append(f"{load_s}\\n{app_s}\\n{mode_s}\\n{graph_s}")
    vals.append(stats[k]["mean"])
    errs.append(stats[k]["std"])

bars = ax_all.bar(range(len(vals)), vals, yerr=errs, capsize=3,
                  color=["#66c2a5" if stats[sorted(stats)[i]]["mean"] < 1.0 else "#fc8d62" for i in range(len(vals))],
                  edgecolor="black", alpha=0.85)
ax_all.set_yscale('log')
ax_all.set_ylabel("Нормализованное время (сек / итерацию, log)")
ax_all.set_title("Все конфигурации (нормализованное время, log scale, N=20)", fontsize=10)
ax_all.set_xticks(range(len(vals)))
ax_all.set_xticklabels(short, fontsize=7)
ax_all.grid(axis="y", linestyle="--", alpha=0.5)
ax_all.set_axisbelow(True)
for bar, val in zip(bars, vals):
    ax_all.annotate(f"{val:.2e}", xy=(bar.get_x()+bar.get_width()/2, bar.get_height()),
                    xytext=(0, 3), textcoords="offset points", ha="center", va="bottom", fontsize=6)
fig_all.tight_layout()
fig_all.savefig(os.path.join(GRAPHICS_DIR, "all_config_normalized.png"), dpi=200)
plt.close(fig_all)
print("Общий график сохранён: all_config_normalized.png")

with open("../data/normalized_stats.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["load","app","mode","graph","iter_raw","n","mean","std","se","ci95","median","min","max","maxrss_mean","majflt_mean","minflt_mean"])
    for k in sorted(stats):
        s = stats[k]
        writer.writerow([k[0], k[1], k[2], k[3], s["raw_iter"], s["n"],
                        f"{s['mean']:.6f}", f"{s['std']:.6f}", f"{s['se']:.6f}",
                        f"{s['ci']:.6f}", f"{s['median']:.6f}",
                        f"{s['min']:.6f}", f"{s['max']:.6f}",
                        f"{s['maxrss_mean']:.0f}", f"{s['majflt_mean']:.0f}", f"{s['minflt_mean']:.0f}"])

with open("../report/analysis_summary.txt", "w", encoding="utf-8") as f:
    f.write("Нормализованные результаты (wall_s / iter), N=20 (без прогрева, df=19, t≈2.093)\\n")

    f.write(f"{'Конфигурация':<48} {'Среднее':>10} {'95% ДИ':>8} {'N':>3}\\n")
    f.write("-"*82 + "\\n")
    for k in sorted(stats):
        s = stats[k]
        load_s = k[0]
        app_name = "read" if k[1] == "graph_traverse" else ("mmap" if k[1] == "graph_traverse_mmap" else k[1])

print("Анализ завершён.")
print("  Графики: pairwise_*.png + all_config_normalized.png")
